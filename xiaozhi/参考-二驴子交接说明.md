## 三、硬件与引脚定义（已改完）

主控：ESP32-S3（16MB flash，**Octal 80MHz PSRAM，已启用 `SPIRAM_USE_MALLOC`**）

> 内存充裕，240×240 帧缓存放 PSRAM 毫无压力，这点不用担心。

### TFT 屏幕：1.54 寸 240×240 ST7789（8 针）

有话说：模块丝印**叫 SCL/SDA，但实际是 SPI 四线**，不是 I²C。CS 低有效，BLK 高电平点亮，RES 低有效复位。

| 丝印针脚 | 模块丝印 | 接 S3 | 说明 |
|---|---|---|---|
| 1 | GND | GND | 共地 |
| 2 | VCC | 3.3V | |
| 3 | SCL | **IO18** | SPI 时钟 SCK |
| 4 | SDA | **IO17** | SPI 数据 MOSI |
| 5 | RES | **IO4** | 复位，低有效 |
| 6 | DC | **IO15** | 数据/命令 |
| 7 | CS | **IO16** | 片选，低有效 |
| 8 | BLK | **IO7** | 背光，**必须接**，否则全黑误判成没驱动 |

> BLK 没接 = 屏幕全黑，很容易浪费时间误判。

### 音频：ES8311 + NS4150B 模块（9 针）

- I²C1 独立总线：SDA→**IO14**，SCL→**IO13**（ES8311 地址 0x18）
- I²S：MCLK IO12、BCLK IO11、WS IO9、DIN IO10、DOUT IO8
- 模块没引 PA 使能脚，音量靠数字音量

### 其他外设

| 器件 | 引脚 |
|---|---|
| 舵机 左右转 pan / 上下 tilt | IO5 / IO6（LEDC 50Hz） |
| 电机 ×4 | IO47、IO48、IO38、IO39（LEDC） |
| WS2812 灯带 | IO21（最多 12 颗） |
| ToF VL53L0X（**计划中，未实现**） | I²C0 SDA IO1 / SCL IO2，地址 0x29 |
| BOOT 键 | IO0 |

### 引脚禁区 —— 改动前必看

```
26~32 : flash        不能动
35~37 : Octal PSRAM  不能动
19/20 : USB          不能动（动了会掉串口）
0     : BOOT 键
```

**剩余空闲 GPIO 只有三个：IO3、IO45、IO46。**
这个约束会直接影响新功能的选型——比如"每个传感器独占一个控制脚"的方案就走不通了。

## 四、踩过的坑（非常重要，别重蹈覆辙）

这几个都是**花了大量时间才定位**的，接手前务必先看。

### 坑 1：没接的外设会 `abort()` → 无限重启

未接的 ES8311 在复位流程里走 `ESP_ERROR_CHECK`，写失败就 `abort()`，板子陷入
"abort → 重启 → abort" 死循环（实测 15 秒重启 **33 次**），屏幕看起来就是不停闪黑。

**解决**：开机先 `i2c_master_probe` 探测（注意参数要 **7 位地址**，ES8311 的 0x30 要右移 1 位），
探测不到就优雅降级用哑 codec。此坑**已修复**，`s3_robot_board.cc` 里保留了这个逻辑，别删。

### 坑 2：I²C 速率受限于上拉电阻（OLED 时代的结论）

S3 内部上拉约 **45kΩ**，上升沿约 800ns。而 400kHz 要求上升沿 <300ns。
物理上不可能达标，实测 400kHz 必定 I2C 超时。
降到 100kHz（放宽到 <1000ns）勉强可用。想跑 400kHz 必须在 SDA/SCL 各加 **4.7kΩ 外部上拉** 到 3.3V。
> 换成 SPI TFT 之后这个问题自动消失了，无需处理。

### 坑 3：虚焊 / 冷焊（用户用裸铜丝手工焊接）

反复出现的"屏幕时好时坏、亮一会儿就灭"**全是冷焊**。

正确焊法（已反复向用户强调）：
1. 线头**先镀锡**（捅进锡里烫一下，让锡均匀裹满，呈银亮色）
2. 焊盘也薄薄挂一层锡
3. 烙铁同时加热线和焊盘，锡流动融合后拿开烙铁
4. **关键：手别动，等完全凝固**——动了就是冷焊
5. **必须用助焊剂**（松香），否则铜的氧化层去不掉，锡根本挂不上
6. 好焊点亮、平滑、圆锥状；发灰粗糙圆球状 = 冷焊，重来

### 坑 4：4 针 OLED 没有硬件复位脚 → 画面"定住"

`panel_config.reset_gpio_num = GPIO_NUM_NC`，模块没引出 RES。
板子软重启时 SSD1306 **硬件上不会被复位**，若重启恰好打断一次 I²C 传输，
它会锁死总线拉住 SDA，之后初始化必定失败，而屏幕仍显示最后一帧 GRAM
—— 表现就是"画面定住"，只能靠模块断电恢复。

**当时写了 `RecoverI2cBus()`（用 GPIO 打时钟 + STOP 条件解锁总线）想软件解决，
但最终定位是硬件短路，这套代码在换 TFT 后已经删掉了。**

### 坑 5：最终杀死 OLED 的真凶 —— 反复用烙铁烫

全链路诊断（值得记住这套方法）：

1. 排软件自动关屏：s3-robot 板**没有任何休眠/关屏逻辑**，只有开机那一次 `disp_on_off(true)` ✅ 排除
2. 降速 400k→100k 对比：无效 → 排除时序问题
3. **加临时诊断打印两条 I²C 线的空闲电平**（开内部上拉后读）
   —— 健康总线空闲必须是 `1/1`，读到 `0` 就是被拉死
4. 结果 `SDA=1 SCL=0`：**SCL 被硬拉到地**，软件救不了硬件短路
5. **关键对比实验**：拔掉屏幕信号线后 SCL 立刻回到 `1`
   → 板子没问题，**是屏幕模块把 IO18 拉死了**
6. 结论：模块大概率被烙铁反复加热烫坏（或 SCL 焊点连锡）

**我们因此决定：彻底放弃 OLED，换 SPI TFT。** 这也是当前最正确的方向。

## 六、待办：舵机跟随人手（方案已讨论，未实现）

用户想让**云台舵机（pan IO5 / tilt IO6）跟随自己的手移动**。

### 已确定的前提

单个 VL53L0X ToF **做不到** —— 它每次只吐一个数（前方约 25° 光锥内的距离），
**没有任何方向信息**。驱动舵机做闭环控制需要"方向误差信号"，至少得两个读数做差分比较。

### 方案对比（已向用户列过）

| 方案 | 原理 | 效果 | 成本 | 接线 |
|---|---|---|---|---|
| **AMG8833 红外热成像阵列** ⭐推荐 | 8×8=64 像素热图，60° 视野，算热点质心得 (x,y) | 最好，真二维 | ~70 元 | 单 I²C，地址 0x69，**不冲突不用 mux** |
| LD2450 毫米波雷达 | UART 直接输出目标 x,y，6m | 很好，不受温度/光线影响 | ~35 元 | UART 两根线 |
| HW-201 ×5（红外反射） | 多个模块的反射强度差分 | 最弱：**仅 2~30cm**、很顿 | ~15 元 | 每个占一个 GPIO + ADC |
| 4× VL53L0X + TCA9548A | 四路距离差分摆十字 | 一般，环速率仅 ~10Hz | ~45 元 | I²C + 复用器 |

**HW-201 的硬伤**：距离只有 2~30cm；DO 只有 0/1 只能乒乓控制会很顿；
深色物体不反射红外；日光下基本失效。**务必选带 AO 模拟输出的 4 针版本**，
AO 能给连续强度值，配 PD 控制才可能平滑。

**为什么推荐 AMG8833**：单个器件解决"手在哪"，不用折腾 I²C 地址冲突，
不用那仅剩的 3 个 GPIO，代码逻辑反而比四路差分简单。

> ⚠️ **剩余 GPIO 只有 IO3 / IO45 / IO46 三个**，
> 这直接否决了"4 个 ToF 各自拉一根 XSHUT"的方案（需要 4 个脚）。
> 多传感器必须走 TCA9548A 复用器（不占额外 GPIO），或选单器件方案。

### 实现这个功能需要做的三件事

1. 加传感器驱动 + 读数任务
2. 写独立的 tracking 任务：按差分/质心算法算误差，PD 控制驱动舵机
3. （可选）注册 MCP 工具，让 AI 能开关跟随模式

**注意：`ServoController` 类已经写好（LEDC 50Hz，IO5/IO6），
但它目前只是个独立对象 —— 没有 MCP 工具暴露，也没有任何 tracking 逻辑在调用它。**

控制逻辑参考（差分式）：

```cpp
int error_x = dist_left - dist_right;   // 左边更近 → 负值 → 向左追
int error_y = dist_up   - dist_down;
servo_pan  += error_x * Kp;             // PD 控制
servo_tilt += error_y * Kp;
```
