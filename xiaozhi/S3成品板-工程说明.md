### 6.4 三层调度（状态 / 情绪 / 待机小动作）

| 层 | 触发 | 播放片段 | 播完去哪 |
|---|---|---|---|
| **状态层** | `SetStatus(STANDBY)` | `dafeiyu_idle` 循环 | — |
| | `SetStatus(CONNECTING)` | `dafeiyu_wake` 一次性（伸懒腰＝唤醒入场） | 回待机；若已在聆听则接 `wait` |
| | `SetStatus(LISTENING)` | `dafeiyu_wait` 循环；**2.6 秒**没转说话 → `dafeiyu_think` | — |
| | `SetStatus(SPEAKING)` | `dafeiyu_speak`（**碎碎念**，真的在叨叨，嘴会动） | — |
| **情绪层** | `SetEmotion(happy/laughing/funny/silly/winking/kissy/loving/delicious/relaxed/cool/confident)` | `dafeiyu_happy` 一次性 | 回当前状态层 |
| | `sad/crying/angry/embarrassed` | `dafeiyu_error` 一次性 | 同上 |
| | `sleepy` | `dafeiyu_yawn` 一次性 | 同上 |
| | `neutral/surprised/shocked/confused` | 不反应 | — |
| **待机层** | 待机空闲 **25~45 秒**随机一次（`esp_random`） | `wake / yawn / eat / happy / dance / hum / pet` 随机一个 | 回 `idle` |

要点：

- **实时性**：`SetStatus()` / `SetEmotion()` 是协议任务调进来的，一次 GIF 装载要
  `lv_malloc` 384KB（canvas 4·w·h + frame w·h）再解首帧（实测 7~16ms），
  且原来还要抢 LVGL 互斥锁。直接在回调里做会卡住 TTS 收包和 AFE 喂数据，
  表现为**播放卡顿 / 语音唤醒失灵**。所以 `Play()` 只登记 `requested_`，
  真正装载统一在 `OnTick()`（LVGL 任务）里做
- **情绪冷却**：服务端每段回复都带 emotion，不加冷却会一句插好几次。
  `kReactionCooldownMs = 15000`，冷却期内的 emotion 直接丢弃
- 素材是**紧贴角色**出图的（210x240，比屏幕窄），`FitImageObject()` 按实际尺寸居中，
  不让 LVGL 按 320x240 拉伸；每帧解码/混色/刷屏比满屏画布省约 34%
- 用 `strcmp` 比状态串（`constexpr const char*` 跨编译单元指针不同，不能用指针比较）
- 状态栏每秒刷新的时钟文本走同一个 `SetStatus`，不匹配四项 → 不切动画
- 一次性片段正在播时收到新情绪会被忽略，避免互相打断
- 原生状态栏 / 字幕 / 表情标签在 `SetupUI()` 里整体隐藏，屏幕背景 `#14161C`
- 资产（assets 分区）比 UI 晚就绪：`pending_` + 120ms `lv_timer` 持续重试，
  `SetEmojiCollection()` 回调里也会补一次起播

## 七、养成玩法 + 网页控制页

### 7.1 Flash 分区（2026-10-30 改过）

```
ota_0   0x20000   3.75MB     ota_1   0x3e0000  3.75MB
assets  0x7a0000  7.5MB  ← 动画 GIF（只读，构建时打进去）

```

改分区表后必须**整片重刷**（`idf.py flash`，不能只 `app-flash`）。
NVS 只有 16KB，养成存档放 `pet` / 界面配置放 `petui` 两个命名空间。

### 7.2 养成玩法（`dafeiyu_pet.h/.cc`）

| 数值 | 初值 | 变化 |
|---|---|---|
| 饱食度 | 60 | 每 60 秒 -1；喂食 +10~25 |
| 心情 | 60 | 每 60 秒 -1；喂 +3~8、摸头 +6、对话 +2（20 秒节流）；饱食度 <20 时额外 -1/分 |
| 亲密度 | 10 | 只涨不跌：摸头 +2、对话 +1 |
| 等级/经验 | 1 / 0 | 每级 100 经验；喂食 +4、摸头 +2、对话 +3；升级播「雀跃庆祝」 |

- 存档：NVS blob，事件触发即存 + 每 60 秒兜底存一次
- 离线衰减：开机时用 `esp_timer` 时间戳补算，**最多算 8 小时**（关机不该把她饿死）
- 显示层消费 `PetGame::ConsumeAction()` → 喂=kEat / 摸头=kHappy / 升级=kSuccess / 饿了=kError

### 7.3 网页控制页（`dafeiyu_web.cc`，端口 80）

浏览器打开 **设备 IP**（日志里 `sta ip:`，当前 192.168.1.7）：

| 接口 | 作用 |
|---|---|
| `GET /` | 控制页（单文件，样式/脚本内联） |
| `GET /api/state` | 养成数值 + 当前配置 JSON |
| `POST /api/food?food=苹果` / body | 喂食（食物名走 `FindFoodInText` 查表） |
| `POST /api/pat` | 摸头 |
| `POST /api/config?bg=%23001A33&clock=1&wallpaper=1` | 改背景色 / 时钟开关 / 壁纸开关，版本号 +1 |
| `POST /api/wallpaper` | 上传壁纸，**body 必须是 320x240 RGB565 原始像素 153600 字节** |
| `GET /api/wallpaper`、`POST /api/wallpaper/delete` | 下载 / 删除 |

壁纸为什么传原始像素：设备端就不用挂 JPEG 解码器，读出来直接给 LVGL
（`LV_COLOR_FORMAT_RGB565`）。转换在网页 JS 里做（canvas 裁切 + 转 RGB565）。
字节序：低字节 `ggGGGBBB`、高字节 `RRRRRGGG`（小端 RGB565）。

### 7.4 摄像头相关

- `SetPreviewImage()`：拍照时**隐藏角色和时钟**，预览图铺满 320x240 并置顶；
  5 秒后（基类的 `PREVIEW_IMAGE_DURATION_MS` 定时器）自动恢复
- **拍照喂食**：拍照时打标记 → 服务端描述回来走 `SetChatMessage()` →
  `FindFoodInText()` 在回话里找食物 → 命中就喂，没命中播「不吃」的反应。
  窗口 60 秒（`kVisionWindowMs`）

### 7.5 固件精简

已做：`ml307_board.cc` / `nt26_board.cc` / `dual_network_board.cc` 改成
`if(NOT CONFIG_BOARD_TYPE_ZHENGCHEN_CAM)`，WiFi 板不再编译 4G 板源码（省约 15KB）。

**`esp-ml307` 组件砍不掉**：`wifi_board.cc` 用它的 `EspNetwork`、

## 八、开机 / 配网 / 验证码界面 + 时钟（2026-10-30 二改）

### 8.1 开机动画（自绘，不依赖角色素材）

`CreateBootScreen()` 建一层全屏 `boot_panel_`：转圈圆环（270° 弧，tick 里每帧 +30°，
1.5 秒一圈）+ 进度条 + 阶段文字 + 三个呼吸圆点。进度按时间推进：

| 阶段 | 时间 | 进度 | 文字 |
|---|---|---|---|
| Wi-Fi | 0~3s | 0~20% | `WiFi` |
| 连服务端 | 3~7s | 20~50% | `LINK` |
| 等 assets | 7s+ | 50~95% | 拿到 IP 后直接显示 IP，否则 `ASSETS` |

assets 就绪 → `FinishBootScreen()` 拉满 100% 显示 `READY`，700ms 后隐藏。

**坑：这个面板只能隐藏不能删除。** `lv_obj_del()` 会走到
`lv_event_mark_deleted()` 遍历 LVGL 全局事件链表，实测必崩（LoadProhibited，
`EXCVADDR` 是个接近 0 的野指针）。改成 `LV_OBJ_FLAG_HIDDEN` 后连续重启 3 次无崩溃。

### 8.2 配网 / 验证码 / 系统消息

基类 `status_bar_` **不再隐藏**，改挪到屏幕底部并重新配色；里面两个标签各司其职：

- `notification_label_` —— 音量、配网提示。加了半透明胶囊底 + 自动换行
- `status_label_` —— 状态文字（待机 / 连接中 / 激活…）
- `sys_label_`（新增）—— `SetChatMessage("system", ...)` 的内容走这里：
  配网提示、激活说明、升级进度
- `sys_code_label_`（新增）—— 从系统消息里抠出**连续 ≥4 位数字**当验证码，
  48 号字居中黄色显示

⚠️ **内置字体是精简字符集**（`font_noto_sans_basic`，890 字，其中 CJK 仅 206 个）。
`饱 / 食 / 验 / 证 / 码` **都没有**，所以：新写的文案尽量避开生僻字；
养成状态条用 `FOOD / MOOD` 英文标签而不是中文。
想显示任意中文得换 `font_noto_sans_common_20_4`（1.26MB，app 剩余空间不够）。

### 8.3 待机时钟 + IP

- 时钟做成左上角**半透明卡片**：48 号 `HH:MM` + 日期 + **IP 常驻**
- IP 来自 `WifiManager::GetInstance().GetIpAddress()`，每 5 秒查一次，拿到就不再查
- **时间源两条路，口径已统一**：服务端 `server_time` 给的是 UTC 毫秒戳，
  时区改用 POSIX `TZ` 表达（`ota.cc` 里 `setenv("TZ", "UTC-8")`），
  不再把偏移加进时间戳；SNTP 兜底写的是 UTC，`localtime()` 按 TZ 换算 → 两边一致
- `MCP` 新增 `self.device.get_ip`：问她"你 IP 是多少"会返回 IP 和网页地址

### 8.4 唤醒行为

`CONFIG_SEND_WAKE_WORD_DATA` 关掉：唤醒后**不再把唤醒词发给服务端**，
只播一声提示音然后进入聆听（和 C3 一致），不会自动开场白。

### 8.5 音频卡顿的真正根因：内部 SRAM 耗尽（2026-10-30 定位）

之前一直按"CPU 抢占"的思路找，全错。逐项排除后，**根因是内部 SRAM 不够**：

先排除掉两条常见误解：

| 猜测 | 实测结论 |
|---|---|
| LVGL 抢 CPU | ❌ `lcd_display.cc:137` 里 `task_priority = 1` 且钉死 core 1，是全系统最低。`audio_output=4`、`opus_codec=2` 都压在它上面 |
| 网络差 / 服务端慢 | ❌ 用户一直连官方 `api.tenclass.net`；从电脑访问同一域名是通的（HTTP 400） |

真正的现象：

```
E httpd: httpd_server: error in select (12)          ← ENOMEM
W httpd_sess: enum_function: Closing invalid socket -1    ← 每秒刷十几条
E esp-tls: [sock=54] select() error: Not enough space
E transport_base: Failed to open a new connection
I SystemInfo: free sram: 1195  minimal sram: 127     ← 只剩 127 字节
```

**内部 SRAM 一耗尽，TLS 握不上、MQTT 连不上、socket 建不出来** —— 这些失败在听感上就是爆音和卡顿。之前横小马-interfaceshttp观察到的偶发 `0x8006`（`ESP_ERR_ESP_TLS_HANDSHAKE_FAILED`）也是同一个根因，不是网络问题。

做了三件事：

| 措施 | 文件 | 效果 |
|---|---|---|
| httpd 瘦身：`max_open_sockets` 7→4、stack 8192→6144、开 `lru_purge`、保活 2s | `dafeiyu_web.cc` | select errors 归零 |
| opus 任务栈 24KB→16KB | `audio_service.cc` | 省 8KB 内部 RAM |
| 布局/时序优化（见下） | `dafeiyu_display.cc` | 说话时带宽让给音频 |

结果 **`free sram 1195 → 20359，minimal 127 → 11515`**。

⚠️ **踩过的坑：`max_open_sockets` 砍太狠。** 先砍到 2，结果 keep-alive 占着槽位不放，后续请求全部挂起（网页轮询时好时坏）。4 个 + 2 秒保活是可用性和内存的平衡点。PSRAM 不能用来放任务栈 —— flash 写操作会禁用 cache，那个窗口里 PSRAM 不可访问会崩。

### 8.6 动态刷新率：说话时给音频让路

内部 SRAM 撑不起 LVGL 双缓冲（`lcd_display.cc` 里的降级路径是常态，实测一定降级回 20 行单缓冲），LVGL 优先级也已经是最低。唯一能腾出来的变量是**每秒刷几次屏**：
每帧 153KB 的 SPI + PSRAM 流量，说话时砍到三分之一。

```cpp
constexpr uint32_t kRefrIdleMs  = 33;    // ~30fps 待机
constexpr uint32_t kRefrSpeakMs = 100;   // ~10fps TTS 播放中
```
用 `lv_display_get_refr_timer()` 拿到 LVGL 刷新定时器，按状态设周期。

### 8.7 待机「随机插曲」——whale-girl 的启发

参考 `whale-girl` 的 STATE_TABLE：它的 `working` 状态不是指示灯，而是由 client 节奏器
**随机插入**的工作插曲（随机触发间隔、随机时长），`think` 才是常态 —— 这招让待机不再重复。

我们这套其实早有 `kMicros`（wake/yawn/eat/happy/dance/hum/pet 随机播），
但间隔是 **25~45 秒**，看几分钟才动一次 —— 这就是用户说的"不灵动"。已改成 **12~30 秒**。

另外抄它一条原则：**零负反馈**。现在 `hunger/mood` 衰减到 0 会让养成数值见底，玩家回来
看到一条饿死的鱼会直接不想玩（实测挂机几小时后 hunger=0/mood=0）。这条要改，见待办。

### 8.8 双布局：桌面模式 / 信息模式

`UiConfig` 加了 `layout` 字段（NVS 存档，改结构会让旧配置回默认，正常），网页「外观」
里可直接切，切换即时生效：

- **桌面模式**（默认）：角色全屏居中，时钟是角落里的小卡片
- **信息模式**：**角色整条往左靠**，右边空出的一竖条给时钟（104×92）和数值（104×60）。
  滚动 enough：屏幕 320、素材 210，靠左后右侧正好腾出 110px —— 不用缩放就拿到了信息区

### 8.9 ⚠️ LVGL 对 image 是裁剪，不是缩放（踩过的坑）

第一版「信息模式」把角色按 `lv_obj_set_size()` 改小到 114×128 想做缩略图，结果画面变成
**右上角一小块 **（用户原话："放右下角怎么显示不是全身是个小窗户口"）。原因：

> LVGL 的 `lv_image` 对象尺寸改小，只是**把画布裁出一小块显示**，画布本身还是 210×240。
> 对象 114×128 = 只显示左上角那一片，看着像从窗口里看局部。

真要缩小只有 `image scale`（软件重采样），代价是每帧多算一遍 + 画质糊 + 音频跟着卡 ——
**结论：不要缩，要么按原始尺寸整只显示、要么整个平移。** 代码里已经写了警示注释。

### 8.10 待机动作改为「数值驱动」（不再随机抽签）

原来 `kMicros` 是纯随机挑片段，跟养成数值毫无关系 —— 玩家喂了半天鱼没反应，养成就没有
反馈闭环。现在按**优先级读数值**决定演哪一段：

```cpp
hunger < 35                → kEat    // 饿：去翻吃的
mood   < 35                → kYawn   // 困 / 无聊：打哈欠
bond  >= 70                → kPet    // 跟你熟了：蹭过来求摸
mood  >= 75 && hunger >= 55 → kDance/kHappy  // 状态好：得意地跳一段
否则                        → 常态 idle 循环
```

两条设计约定：

1. **走「可爱的需求表达」而不是「惨状」** —— 饿是这个世界上最可爱的事，不是惩罚。
   数值一眼看得出，但画面永远是活蹦乱跳的一条鱼（呼应 whale-girl 的零负反馈原则）。
2. **同一诉求不重复演** —— `last_idle_clip_` 记着上次演了啥，相同的就把下次再推迟
   `kMicroMinMs`，否则隔十几秒重复一次「翻吃的」，看着像卡碟。

`PickIdleActionByStats()` 是 `DafeiyuDisplay` 的成员函数（因为 `Clip` 是嵌套类型，
放文件里那个匿名 namespace 会编译不过）。

`clock_panel_` 内部改成了 flex 竖排，所以切布局只要改 cross 对齐（左对齐 / 居中），
不用逐个挪标签。`FitImageObject()` 记住素材原始宽高，切布局时重算缩放。

### 8.5 播放卡顿的另一半原因

GIF 解码 + 渲染都在 **LVGL 任务**里，`LvglGif` 新增 `SetFrameSkip()`：
说话（TTS 播放）时跳一帧渲染一帧，解码和刷屏的 CPU 直接让给音频。
（`elapsed < gce.delay*10` 之后才判跳帧，所以节奏不会被打乱）

### 8.11 待机界面的最终分区布局（2026-10-31）

之前几轮一直在「角色占满屏 + 信息挤在角落」里打补丁，根源是硬约束：
**素材 210×240 vs 屏幕 320×240 —— 角色横占 66%、纵占 100%，信息层怎么挪都没地方。**

最终方案是动素材本身 + 一刀切分区：

```
┌──────────────────────┬────────┐
│ 11:29                │        │
│ 10月31日 周六        │        │   左 158px = 信息区（kInfoPanelW）
│ 192.168.1.7          │        │   右 150px = 角色地盘
│                      │  大肥鱼 │
│                      │        │
│ 饱食 ▓▓▓▓░  78       │        │
│ 心情 ▓▓▓░░  65       │        │
│ 亲密 ▓▓░░░  53       │        │
│ 等级2 经验73         │        │
└──────────────────────┴────────┘
```

配套的三处调整：

- **原来的「桌面模式 / 信息模式」双布局删掉了**。两套模式都没能解决屏不够宽的问题，
  是无效复杂度。`ApplyLayout()` 保留参数以兼容存档结构，但不再切换摆放。
- **基类的 `status_bar_` 整个隐藏**。它自带那行「时间 + 电量 + 网络」跟我们自己的
  时钟卡片重复，而且是没标签的图标，用户反馈「看不懂是啥」。
  配网提示 / 验证码 / 音量保留，走有明确上下文的 `sys_label_` / `notification_label_`。
- **数值从 2 条扩到 4 条**（饱食 / 心情 / 亲密 / 等级+经验）。养成系统 `PetState`
  一共就这 5 个字段，现在**全部**都显示了，没有遗漏项。

### 8.12 ⚠️ GIF 缩小必须先在电脑上预处理（两个坑）

素材从 210×240 缩到 **150×171**，由 `_resize_assets.py` 完成。
**绝不能在 ESP32 上用 LVGL 缩放**：运行时缩放要开软件重采样，每帧多算一遍，
这台设备内部 SRAM 极其紧张（见 8.5），会直接拖垮音频。

踩到的两个坑，都会表现为**角色轮廓挂着一圈虚影**：

| 坑 | 现象 | 修法 |
|---|---|---|
| **写死 `disposal=2`** | 每帧后强制恢复背景，而原素材是帧间叠加的增量动画（35/36 帧是局部增量），解码器擦背景擦不干净 | 跟随原图：`disposal` 从 `im.info` 读，原图没写就别传这个参数 |
| **LANCZOS 在强边缘产生 ringing + 半透明像素被量化成杂色** | GIF 只有 1 位 alpha，缩放混出的半透明边缘会被量化抖动成一圈毛边 | 加 `reducing_gap=3.0` 做预滤波；再把 alpha 按 110 阈值二值化后保存 |

验证方法（改动后务必跑）：

```
局部增量帧  35/36   ← 必须跟原图一致（写成 0/36 说明每帧全幅，会丢 disposal 语义）
前8帧半透明像素  全 0  ← 有非零就会出毛边
```

顺带收益：素材 **5.27MB → 2.94MB**，加载 `load=3ms`。

### 8.13 汉字字库：自己造一个「basic + 所需汉字」

`charsets/common.json`（6845 字）确实什么字都有，但字体源文件是 basic 的 7.7 倍，
app 分区只剩 0.77MB，**直接换绝对装不下**。

走的第三条路 —— `_build_font.py` 重生成一个同名、同符号的字库：

1. 下载 Noto Sans SC 源 TTF（`_font_tools/`，注意 GitHub raw 直连被拒，走 cdn.jsdelivr.net）
2. `fontTools subset` 出「basic 的 890 码点 + UI 需要的汉字」的子集 TTF
3. `78/lv_font_conv`（node）转成 LVGL 的 C 文件，覆盖 `managed_components/78__xiaozhi-fonts/src/font_noto_sans_basic_*.c`

**符号名和文件名都不变，所以调用方代码一行都不用改。**

```
890 码点 → 948 码点（+58 个 UI 汉字）
app 体积反而更小 —— 因为改用单一 TTF 源，省掉了原多源合并的重复字形
```

要加字：改 `_build_font.py` 里的 `CJK_EXTRA` 那串字重跑即可（约 1 分钟）。

⚠️ **代码里写汉字有两个必踩的坑**：

- **标签字体必须换成中文的 `font_noto_sans_basic_14_1`**。`lv_font_montserrat_*`
  只有拉丁字符，汉字渲染出来是一片空白。
- **`snprintf` 的 buf 要给够**。汉字在 UTF-8 里占 3 字节，「等级」俩字就 6 字节，
  原来 `char buf[20]` 装 `"等级%u 经验%u"` 会触发 `-Werror=format-truncation`。改成 `buf[32]`。
